Code signing is not the same as a safe download

A checksum, a valid digital signature and a reputation warning answer different questions. Understanding the difference is more useful than treating any one signal as a green light.

Published 20 October 2026 · Educational guidance, not a scan of a particular file

Three independent questions

Integrity, publisher identity and reputation

Imagine finding two installers with identical names. One came from the developer's published release and one from an unknown mirror. The name alone cannot tell you whether their contents match. Even if a file was unchanged, it may still be unsafe for reasons that a checksum cannot detect.

SHA-256: did the bytes match?

A cryptographic hash is a fingerprint of the contents. If your locally calculated SHA-256 matches a trusted reference, this supports byte-for-byte integrity. It does not identify the author or tell you whether the software's behavior is safe. A checksum copied from the same untrusted mirror has limited independent value.

Authenticode: who signed this artifact?

Windows Authenticode can bind a software publisher's signing identity to a file and detect relevant changes after signing. A valid signature can help establish provenance and integrity relative to the signer. It does not mean Microsoft independently audited the application's code, or that its functions are harmless.

SmartScreen: what does Windows know about reputation?

Microsoft Defender SmartScreen considers file and publisher reputation. New, uncommon or unsigned programs may attract warnings; a warning is a reason for caution, not automatic proof of malware. Even newly signed software may need to build reputation.

Verify without running the file

Read the evidence before considering execution

Start at the project's official release page and verify the exact artifact name and version. Windows includes PowerShell commands for viewing a file's SHA-256 hash and Authenticode status. Point these commands at a file you have already obtained from a trusted source; they inspect metadata without launching the installer.

Check a checksum

Get-FileHash -LiteralPath "C:\path\to\file.exe" -Algorithm SHA256

Compare the result against a SHA-256 published through an independently trusted channel. A mismatch is a reason to stop and investigate, never to ignore verification.

Inspect a signature

Get-AuthenticodeSignature -LiteralPath "C:\path\to\file.exe"

Look at the reported signature status and signer information. An unsigned file has no Authenticode signer to verify. Do not disable Windows security protections merely to silence a warning.

What does a trustworthy release note include?

An honest release note distinguishes the exact version, source commit, checksum, signing status and platform-specific test evidence. It also states which tests were not performed. Unsigned previews must be identified as unsigned; a verified hash is not a replacement for publisher authentication.

For MalGuard specifically, use the current release-status page and published evidence page for changing availability and limitations rather than inferring them from this general guide.
