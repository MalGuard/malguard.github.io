Start in four steps

  1. Paste the public website link

    Use Website scan for the received page and known URL reports. Private network addresses and non-web protocols are blocked.

  2. Watch the progress beside the scan

    The result appears on the same screen. View details opens the evidence, coverage, linked-page inventory and threat sources.

  3. Choose whether to inspect linked pages

    Inspect linked pages opens a confirmation. The original assessment remains visible while the additional destinations are checked.

  4. Review before interacting

    Read warnings and incomplete coverage before signing in, paying or downloading. Export the report if you need to share the observations.

Training transcript
  1. Welcome to GameScam Guard. Follow the pointer through this harmless training example. First, enter a public website address.
  2. Select Start scan. Watch the progress here, then read the result on the same screen.
  3. Open View details, then Coverage. This shows twenty distinct static checks, and which checks completed.
  4. Choose Threat sources. Review the submitted address, each redirect, and the final destination separately.
  5. For a wider inspection, select Inspect linked pages. Read the scope before confirming.
  6. Select Scan public pages. This example adds a simulated threat report from a linked destination. The original assessment stays visible, so you can see why the expanded result changes.
  7. Open Self-test and select Run self-test. These thirty-eight harmless examples check selected detection rules and security boundaries.
  8. Back in Scan, this second example simulates a source outage. An incomplete inspection means evidence is missing. Retry later before relying on that result.
  9. Finally, open Settings to review your sources and privacy choices. Use these observations to make an informed decision before signing in, paying, or downloading.

Read the result

No known threat observed

The completed checks did not observe a known threat. This describes the evidence received at that time.

Use caution

The page or its redirect path supplied warning signs. Review the evidence and the actual destination.

Reported threat

A configured threat source reported an address in the observed path, or a linked destination supplied additional threat evidence. Avoid interacting with it.

Incomplete inspection

Required content or source evidence was unavailable, rejected, timed out or exceeded a limit. Retry later or use another independent assessment.

What the engine checks

One static website-analysis engine has these 20 checks. They are distinct rules, not 20 independent antivirus vendors. JavaScript and files are not executed.

  1. URL identity

    Checks IP-literal and mixed-script hostnames.

  2. Gaming brand impersonation

    Checks deceptive brand tokens in the actual hostname.

  3. Sensitive form destinations

    Checks where password and payment forms send data.

  4. Sensitive form methods

    Checks for sensitive values exposed through GET.

  5. Verification code collection

    Checks code forms for insecure or external destinations.

  6. Wallet recovery requests

    Checks actual form controls requesting wallet secrets.

  7. Payment transport

    Checks payment fields for unencrypted submission.

  8. Active mixed content

    Checks HTTP script references on HTTPS pages.

  9. Encoded dynamic code

    Checks inline script syntax for decoding inside dynamic evaluation.

  10. Credential and network patterns

    Checks inline code combining credential reads and external requests.

  11. Clipboard execution traps

    Checks copy-to-clipboard code paired with shell-run instructions.

  12. Script redirect targets

    Checks literal cross-origin navigation assignments without executing them.

  13. HTML redirect targets

    Checks meta refresh destinations without following them.

  14. Displayed link mismatch

    Compares explicit URL labels with actual link hosts.

  15. Embedded frame boundaries

    Checks active data frames and external sign-in frames.

  16. Legacy active plugins

    Checks executable plugin MIME types and ActiveX objects.

  17. Persistent browser code

    Records service worker registration; presence alone is not a threat.

  18. Encoded embedded documents

    Checks executable HTML data documents without decoding or running them.

  19. Browser mining patterns

    Checks specific mining endpoints and known mining script references.

  20. External script integrity

    Records missing integrity metadata; absence alone is not a threat.

Article: layers, evidence and independent engines

A layer is useful when it observes something different. A hostname check can identify misleading brand tokens; a form check can inspect the destination of password fields; a URL reputation source can report an already known address. Repeating the same observation under several names does not add independent detection power.

GameScam Guard combines static HTML rules with configured URL intelligence. Its source and coverage views identify what was inspected and what was unavailable. A negative reputation observation means that the source did not list that exact URL in the checked data; it does not establish the identity or future behavior of the operator.

Evidence quality matters more than an engine count. An independently maintained evaluation should report the sample selection, collection time, missed threats, false alarms and latency. The built-in fixtures check selected functions; they do not measure detection of every possible threat.

Article: why a redirect can change the evidence

A link can pass through several addresses before delivering a page. Checking only the first and last can overlook an intermediate address that has a threat report. This engine checks each distinct address in a completed guarded HTTP chain, within four redirects and five unique addresses.

The same policy is applied to the submitted page and linked pages. Additional linked-page evidence can change the expanded assessment while preserving the submitted-page assessment. An outage is reported as missing coverage rather than invented evidence of malware.

For example, a training page may have no known report, while one linked destination has a simulated report. The expanded result changes because its scope now includes that destination. The report explains that scope and retains the earlier assessment.

Privacy and limits

  • Only public HTTP/HTTPS pages are eligible. Pages behind sign-in, payment or access controls are not fully inspected.
  • The optional isolated snapshot disables page JavaScript, downloads and outbound requests. It is a visual snapshot, not a behavioral malware detonation service.
  • At most 128 discovered public page targets are queued after confirmation. Linked-page HTML has a 2 MiB per-page cap and a 96 MiB total receive budget. Omitted or unavailable work stays visible.
  • When enabled, URLhaus receives the full queried URL, including its path and query. Avoid pasting password-reset links, private sharing tokens or sensitive queries. The optional phishing feed performs local exact-URL matching after downloading a fixed feed.
  • History and saved queue progress are stored in this browser when enabled. Settings can disable local history. Saved snapshots are not retained in history.
  • GameScam Guard inspects website links. Direct file contents belong to the separate GTA Guard workflow and are not analyzed here.

Check this app

Open Self-test and choose Run self-test. The current diagnostic exercises 38 selected synthetic cases: 20 detection/context fixtures, 14 benign controls and four security-boundary checks. A pass describes those functions, not this physical device or every website. Failures need investigation before relying on that function.

If something does not finish

Source unavailable / Not configured

Read Settings and Threat sources. A source without credentials or a current response is not counted as a completed source.

Rate limit

Wait one minute and retry. The last saved linked-page batch can be resumed while its capability remains valid.

Report expired

Start a new scan; report and queue capabilities expire after 30 minutes.

Private address blocked

Use a public website URL. Localhost and cloud-metadata destinations are intentionally excluded.

Reproduce the selected-fixture evaluation

20 of 20 expected rule observations matched; 14 of 14 benign controls produced no warnings in this run. These developer-selected cases do not estimate real-world detection accuracy.
