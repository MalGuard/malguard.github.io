GTA GUARD · SECURE SANDBOX

Fix Secure Sandbox compatibility errors.

Plus and Pro behavioral analysis stays locked until MalGuard proves containment, Windows Sandbox isolation and a harmless real execution probe. Use this guide to fix the host instead of bypassing the safety gate.

Hybrid Isolation

When local behavioral isolation does not certify.

GTA Guard 0.7 adds an optional Disposable Cloud Inspection fallback. It is not a replacement for Windows behavioral execution: the uploaded copy is inspected without executing the Windows sample, the sandbox has deny-all networking, and the disposable environment is destroyed after the job. Because a file leaves the PC, this fallback is opt-in.

Use local isolation when possible

Verified Windows Sandbox remains the preferred path for Plus/Pro behavioral execution. If it certifies, no Cloud Inspection is needed for the behavioral step.

Cloud fallback stays fail-closed

If local execution cannot be proven, Cloud Inspection may add non-executing evidence but it cannot mark the sample SAFE. GTA Guard keeps the missing dynamic evidence visible.

Windows setup

Start with the host requirements.

Confirm hardware virtualization

Open Task Manager → Performance → CPU and confirm Virtualization: Enabled. If it is disabled, enable Intel Virtualization Technology / VT-x or AMD-V/SVM in UEFI/BIOS, then restart Windows.

Enable Windows Sandbox

Press Win + R, type optionalfeatures, open Windows Features, enable Windows Sandbox, apply the change and restart if Windows asks.

Open Windows Sandbox once

Launch Windows Sandbox from Start. It must reach the Windows desktop. A black window or cube that never reaches the desktop means the host still has a startup problem.

Run GTA Guard certification again

Open GTA Guard → Security Health → Secure Sandbox compatibility → Re-check real Sandbox execution. Open Advanced diagnostics only if the check still fails.

Diagnostics

Check the Windows virtualization stack.

Run these read-only checks in PowerShell. The feature check may require PowerShell opened as Administrator.

Windows Sandbox feature

Get-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM

Expected: State : Enabled.

Required services

Get-Service vmcompute,hns | Select-Object Name,Status,StartType

vmcompute and hns should normally be running when the virtualization stack is active.

Hypervisor boot setting

bcdedit /enum "{current}"

Look for hypervisorlaunchtype Auto. Do not change boot settings merely to silence a MalGuard error; use the diagnostic result to identify the cause first.

Black screen / blue cube test

If normal Windows Sandbox hangs during graphics startup, create a text file named sandbox-test.wsb with this harmless configuration and open it:

<Configuration> <VGpu>Disable</VGpu> </Configuration>

If that opens, the host can start Windows Sandbox without vGPU. GTA Guard's isolation configuration also disables vGPU.

Do not bypass the isolation gate.

Do not disable network isolation, mapped-folder protections, containment checks or execution proof just to make Plus/Pro turn green. Standard scanning remains available while Sandbox certification is being fixed.

Error codes

What the Advanced diagnostics codes mean.

NO_ISOLATION_BACKEND_ISOLATION_CERTIFIED

This is a summary error. Read the failures array underneath it. On a Windows PC, the most useful entry is usually the code for windows-sandbox.

SANDBOX_SELF_TEST_TIMEOUT

Windows Sandbox was found, but the isolated guest did not return its self-test result before the deadline. Update to the latest GTA Guard build, close any stuck Sandbox window, restart Windows if needed, verify that Sandbox opens manually, then run Re-check again. Newer builds allow up to 60 seconds for slow Windows Sandbox startup.

WINDOWS_SANDBOX_UNAVAILABLE / SANDBOX_SELF_TEST_LAUNCH_FAILED

MalGuard could not find or launch Windows Sandbox. Confirm Virtualization is enabled, Windows Sandbox is enabled in Windows Features, restart the PC, and verify that Windows Sandbox itself opens before retrying MalGuard.

CONTAINMENT_PROBE_NOT_INSTALLED

The trusted native containment component is missing from the installed package. Reinstall the latest official GTA Guard installer and verify its SHA-256. Do not download a replacement probe from a third-party site.

CONTAINMENT_PROBE_FAILED

The native CPU, memory, process-count or kill-on-close enforcement test failed. Keep Plus/Pro disabled, restart the app or PC, and inspect the detailed containment fields. Do not bypass this check.

SANDBOX_SELF_TEST_FAILED

The guest started but one of the required isolation properties was not proven, such as read-only input, writable bounded output or disabled default network route. Use the returned details object to identify which property failed.

SANDBOX_EXECUTION_SELF_TEST_BLOCKED

This is usually a downstream result. MalGuard does not run its harmless execution proof until containment and isolation certification have both passed. Fix the earlier failure first.

MALGUARD_MICROVM_UNAVAILABLE / malguard_vm_engine_unavailable

These are fallback-backend status messages. If windows-sandbox is available and can certify successfully, the missing fallback engines do not need to be installed just to use Windows Sandbox.

What a successful check looks like

Advanced diagnostics should report localProbeOk: true, nativeContainment.ok: true, isolation accepted, executionCertified: true and releaseReady: true.

Still failing?

Copy the complete Advanced diagnostics JSON from GTA Guard. Keep the error code, failures array, blockers, nativeContainment, isolationSelfTest and executionProbe fields. Do not include unrelated personal files or real malware samples.
