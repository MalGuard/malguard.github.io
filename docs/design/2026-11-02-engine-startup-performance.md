# Engine startup performance repair

The production homepage returned HTTP 200 and DNS resolved correctly, but mobile runtime inspection reproduced a real main-thread stall. At 4x CPU throttling, live studio generation through `PMREMGenerator.fromScene()` caused a 4,047 ms task; a menu interaction could time out while initialization ran. A successful HTTP response alone did not prove responsiveness.

The visual model, meshes, camera, lighting configuration, animation timeline, product identities and existing poster are unchanged. The original RoomEnvironment was prefiltered offline at its original 256px cube resolution and stored in a gzip-compressed Radiance CubeUV atlas (243,232 bytes). Native gzip streams decode it where available; the bundled MIT-licensed fflate fallback supports older browsers. No visitor needs to render or blur the studio. Short yields between geometry groups let input and painting proceed during construction.

3D preparation now runs after the initial page load and an idle opportunity. Near-view preparation may fetch the module, but creates no WebGL scene and requests no studio asset until at least 65% of the engine is visible. The small existing poster remains available throughout preparation. Reduced motion still loads no 3D, and initial rendering starts at simulation time zero.

Local Chromium mobile verification at 390x500 with touch and 4x CPU throttling measured navigation responding in 131 ms and a longest task of 523 ms. These are synthetic fixture results, not a field guarantee. The matching 1440px studio render at time zero had a mean absolute RGB difference below 0.016 on a 0–255 scale against the pre-repair render; the existing poster was not replaced. Actual visual inspection confirmed the same appearance.

Regression coverage checks no below-fold GPU initialization or studio download, initial touch navigation, startup task duration, original geometry and combustion, native-gzip fallback, reduced-motion transitions, four viewport widths, rod alignment, drag, pause, context loss and poster fallback. Build helpers: `tools/bake-product-engine-environment.mjs` produces the original PMREM half-float buffer in an offline browser; `tools/pack-engine-environment.py <metadata.json> <half-floats.bin> <output.hdr.gz>` packs it. `node tools/build-product-engine.mjs` rebuilds the runtime module using the repository's pinned dependencies.
